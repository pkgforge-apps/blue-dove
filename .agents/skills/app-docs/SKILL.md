# App docs

The site in `docs/` is VitePress, managed with bun, deployed to GitHub
Pages by `.github/workflows/docs.yml` at
`https://pkgforge-apps.github.io/<name>/`.

The theme extends VitePress but must never look stock. Each app gets its
own palette, type and home page.

## Where things live

| File | Holds |
|------|-------|
| `.vitepress/app.ts` | name, slug, description, accent: the one place the identity is set |
| `.vitepress/config.mts` | nav, sidebar, head tags |
| `.vitepress/theme/style.css` | the `--app-*` tokens and VitePress overrides |
| `.vitepress/theme/components/Home.vue` | home page layout |
| `.vitepress/theme/components/Downloads.vue` | per-platform download links to the latest release |
| `index.md` | home page copy, in frontmatter |
| `guide/*.md` | the guide |
| `public/` | favicon and logo, generated by `scripts/icons.sh` |

## Personalize

1. **Palette.** Take the two gradient stops from `assets/icon.svg` and
   set `--app-accent`, `--app-accent-2`, `--app-accent-strong` (a darker
   accent for hover), `--app-glow` and `--app-tint` (the accent at low
   alpha) in `style.css`, for both `:root` and `.dark`. Tint the
   backgrounds (`--vp-c-bg*`, `--vp-c-divider`) slightly toward the
   accent so the whole site carries it. Set `accent` in `app.ts` too.
2. **Type.** Pick a body face that fits the app's character, from
   fontsource: `bun add -d @fontsource-variable/<font>`. Import it in
   `theme/index.ts`, set `--vp-font-family-base`, and remove the
   template's Figtree. Keep JetBrains Mono for code unless there is a
   reason.
3. **Home page.** Write `tagline`, `lead` and three to six `features`
   in `index.md`. Add a real screenshot as `public/screenshot.png` and
   set `screenshot: /screenshot.png`. Restructure `Home.vue` when the
   app deserves more than the stock sections (a demo, a comparison with
   the app it replaces, keyboard shortcuts).
4. **Guide.** Replace the introduction, and add pages for real tasks.
   Register each page in the sidebar in `config.mts`.

## Rules

- Write for users, in plain sentences. No marketing filler, ASCII only.
- Document behavior in the same change that adds or changes it.
- Commit `bun.lock`. Install with `bun install`, add packages with
  `bun add -d`, never by editing `package.json` by hand.

## Preview

```sh
cd docs
bun install
bun run dev        # live preview
bun run build      # what CI runs
```

Look at the result in a browser, light and dark, desktop and narrow
widths, before calling it done.
